# Greasy Fork setup

Status: **pending**. There is no real userscript or Greasy Fork listing yet, so import and webhook delivery cannot honestly be verified.

## First real script

1. Create and test the script locally.
2. Merge or push the validated script to `main`.
3. Run `npm run raw-urls` and copy that script's branch-based raw URL.
4. Sign in to Greasy Fork in a normal, user-controlled browser session.
5. Open <https://greasyfork.org/en/import> and import the raw `.user.js` URL.
6. Review the listing and choose automatic source synchronization.
7. Record the returned Greasy Fork ID and public URL in `userscripts.json` and the script README, change its status to `published`, and commit that non-secret metadata with the appropriate script version update if its metadata changed.

Do not put passwords, cookies, tokens, or webhook secrets in this repository.

## Configure the repository webhook

Do this only after at least one Greasy Fork listing is linked to a raw file in this repository.

1. Open Greasy Fork's webhook setup page while signed in.
2. Obtain the GitHub payload URL and webhook secret Greasy Fork generates for your account.
3. In the GitHub repository settings, add a webhook with:
   - Payload URL: exactly the URL supplied by Greasy Fork.
   - Content type: the value Greasy Fork currently instructs, normally JSON.
   - Secret: exactly the secret supplied or generated by Greasy Fork.
   - Events: push events only.
   - Active: enabled.
4. Prefer entering these values on GitHub's website in your signed-in browser. If you explicitly ask Codex to use `gh api`, provide the secret only through hidden terminal input or a protected temporary environment variable; never echo it, and remove the temporary value immediately.
5. When there is a genuine userscript change, increment its version, validate it, publish it through `main`, and verify both the GitHub webhook delivery and Greasy Fork update.
6. Do not make a meaningless version bump just to manufacture listing activity.

## Every later script

A new GitHub folder does not create a Greasy Fork listing. Import each new raw `.user.js` URL once. After registration, the repository webhook can maintain its updates.

Avoid moving or renaming a published `.user.js` file because that changes its raw URL. If a move is necessary, update the Greasy Fork source-sync URL during the same planned migration.

## Normal publishing sequence

1. Create a focused branch.
2. Create or edit one userscript.
3. Update its README and manifest entry when needed.
4. Increment `@version` for an existing script.
5. Run `npm test`.
6. Commit and push the branch.
7. Open a pull request and wait for GitHub Actions.
8. Obtain user review and authorization before merging.
9. Merge to `main`; this is the Greasy Fork publication signal for registered scripts.
10. Verify Greasy Fork after important changes or when webhook behavior has recently changed.

References: [import scripts](https://greasyfork.org/en/import), [metadata keys](https://greasyfork.org/en/help/meta-keys), [code rules](https://greasyfork.org/en/help/code-rules), and [API/webhook overview](https://greasyfork.org/en/help/api).
